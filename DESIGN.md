# Sentinel-DPDP — Design Specification

## 1. Product purpose

**Sentinel-DPDP** is a DevSecOps compliance control plane. It scans code repositories for personal-data leaks that breach India's **Digital Personal Data Protection (DPDP) Act 2023** and DPDP Rules 2025. It looks for Aadhaar, PAN, phone, email, UPI and health/financial data flowing into logs, LLM prompts, DB schemas and consent UIs. For each finding it opens an **auto-fix Pull Request** and verifies the fix before the PR is offered.

**Primary users:** CTOs and engineering leads at Indian startups, FinTechs, SaaS companies and dev agencies, plus DPOs who need audit evidence.

**Core job-to-be-done:** *"Show me how exposed this repo is under DPDP, why each finding matters legally, and give me a safe one-click fix."*

## 6. Component inventory

Every data component supports four states: **Empty**, **Scanning/Loading**, **Results**, **Error**. Loading uses skeletons that keep the layout stable, never a spinner alone.

### 6.1 Top bar
- **Contents:** shield logo + "Sentinel-DPDP"; repo selector (`github.com/acme/fintech-api`, branch `main`); scan status pill; primary **Run Scan** button; user avatar.
- **States:**

| State | Behavior |
|---|---|
| Empty | No repo connected. Selector reads "Connect a GitHub repo"; Run Scan is disabled with a tooltip explaining why |
| Scanning | Run Scan becomes "Scanning… 42%" with a progress bar, `aria-busy="true"`, and a Cancel option. Status pill reads "Scanning 1,204 files" |
| Results | Pill reads "Last scan 2 min ago · 14 findings" |
| Error | Pill turns critical with an icon and the text "Scan failed: auth expired", plus a "Retry" link |

### 6.2 Repo Risk Score gauge (left)
- Semicircular SVG gauge (e.g. **82/100 Critical**), a band label ("Critical Risk · DPDP Non-Compliant") and a delta pill ("+18 pts since e4f9b2").
- **States:**

| State | Behavior |
|---|---|
| Empty | Grey track showing "—" and "Run your first scan" |
| Scanning | Shimmering track with the previous score dimmed |
| Results | Arc color and **text band label** (Low / Medium / High / Critical) |
| Error | "Score unavailable" with a retry button |

### 6.3 Severity breakdown cards (left)
- Three cards: Critical 4 (octagon icon, "Action Required"), High 6 (triangle, "Review Today"), Medium 4 (circle, "Scheduled"). Clicking a card filters the findings table, so the cards act as toggle buttons with `aria-pressed`.
- **States:**

| State | Behavior |
|---|---|
| Empty / zero | "0" with an ok check |
| Scanning | Skeleton |
| Results | Counts shown |
| Error | Hidden, with an inline error |

### 6.4 DPDP coverage chips (left)
- Sec 5 Notice, Sec 6 Consent, Sec 8(5) Security Safeguards, Sec 8(7) Erasure. Each chip shows a status icon and text ("Compliant", "2 issues", "4 leaks"). An "Export DPDP audit PDF" link sits below.
- **States:**

| State | Behavior |
|---|---|
| Not scanned | Neutral chip, "Not assessed" |
| Scanning | Pulse |
| Results | Ok / warn / critical |
| Error | "Unknown" with a help link |

### 6.5 Findings table (center)
- **Header:** title, search box and PII filter chips (All 14 · Aadhaar 4 · PAN 5 · Phone 3 · UPI 2).
- **Columns:** File:Line (mono, link), PII Type (badge), Sink (Log / LLM Prompt / DB Schema / Consent UI), DPDP Section, Severity (icon + text).
- **Interaction:** the selected row gets an accent left border and `aria-selected="true"`. Rows are focusable, ↑/↓ moves between them, Enter opens the detail. Columns are sortable with `aria-sort`.
- **States:**

| State | Behavior |
|---|---|
| Empty (pre-scan) | Illustration with a "Run Scan" CTA |
| Clean | "No DPDP leaks found 🎉" plus a badge to share |
| Scanning | Streaming rows appear as they are found, announced via a polite live region |
| Results | Rows shown |
| Error | Inline banner with retry. Partial results are kept |

### 6.6 Finding detail: side-by-side diff viewer (center)
- **Breadcrumb:** `fintech-api / app / kyc / service.py (Line 42)` · rule `DPDP-RULE-085-AADHAAR-MASK`.
- **Left pane, "Vulnerable":** `- logger.info(f"KYC {aadhaar}")` on `#381017`.
- **Right pane, "Fixed by Sentinel Auto-Fix":** `+ logger.info(f"KYC {mask_aadhaar(aadhaar)}")` on `#0E3020`.
- Changed lines must also carry the `-`/`+` gutter glyphs **and** "Removed"/"Added" screen-reader text, so color is never the only signal. A toggle switches to a unified view for narrow screens.
- **Detected PII in the code preview is shown already redacted** (via `/api/redact`), so the UI never re-exposes raw Aadhaar values.
- **States:**

| State | Behavior |
|---|---|
| None selected | "Select a finding to inspect" |
| Generating fix | Skeleton in the right pane, "Gemini drafting fix…" |
| Results | Diff shown |
| Error | "Could not generate a safe fix. Manual remediation guidance" with a docs link |

### 6.7 DPDP citation card (center)
- Banner "Section 8(5) — DPDP Act, 2023", a blockquote of the statutory text, a penalty note ("up to ₹250 crore"), and a "Read section text →" link that opens in a new tab with an announced external icon.
- **States:** loading skeleton · results · error ("Citation unavailable", with the section number still shown).

### 6.8 Auto-Fix PR panel (right)
- **Header:** PR preview badge and target branch.
- **Verification checklist:** each check shows an icon + text + detail:

  - ✓ No new findings introduced
  - ✓ Compiles / tests pass (142 passed)
  - ✓ Masking format verified
- **PR preview:** branch `fix/dpdp-mask-kyc-aadhaar`, title `fix(dpdp): mask Aadhaar in KYC logs`, commit summary.
- **Actions:** primary **Open Pull Request** (shortcut ⌘/Ctrl+Enter); secondary "Export .patch".
- **States:**

| State | Behavior |
|---|---|
| Empty | "Select a finding with an available fix" |
| Verifying | Each check shows a spinner and its "Running…" text. The button is disabled with `aria-disabled` and the reason |
| Ready | All checks pass; the button is enabled |
| Check failed | Failed item shows a critical icon and the reason. The button is replaced by "View failure log" |
| PR opened | Success toast with a link to the PR (`#128`) |

### 6.9 "Ask the Auditor" voice drawer (right, collapsible)
- **Header:** "Ask the Auditor · DPDP Legal & DevSecOps AI", a disclosure button with `aria-expanded`.
- **Mic button:** large circular button labelled "Gemini Live (Voice Audit)", with a prompt hint below it.
- **Transcript:** chat log (`role="log"`, `aria-live="polite"`), user and auditor bubbles.
- **Text input:** fallback with send and attach buttons. Voice is never the only way to ask.
- **States:**

| State | Behavior |
|---|---|
| Collapsed | Header only |
| Idle | Mic button and hint |
| Listening | Mic is `aria-pressed="true"`, live waveform, text "Listening… press Esc to stop" |
| Thinking | Typing indicator |
| Answer | Answer shown with citations linked to sections |
| Mic denied / error | Inline message pointing to the text input |

### 6.10 Footer chip
- "Powered by Gemini · Gemma redaction · BigQuery telemetry". Static, in `text-secondary`.

## 7. Accessibility

- **Contrast (WCAG 2.2 AA):**
  - `#F0F4F8` on `#0B0D10`/`#14171C` is about 17:1, and `#94A3B8` on `#14171C` is about 7:1, so both pass.
  - `#64748B` on `#14171C` is about 3.9:1. Use it only for non-essential text (line numbers, placeholders) or at ≥18px.
  - Severity text colors on L1 surfaces all exceed 4.5:1.
  - Primary buttons use `#0B0D10` text on `#00F0FF` (about 14:1).
- **Never color-only:**
  - Severity always shows icon + text: octagon "Critical", triangle "High", circle "Medium".
  - Checklist items use ✓ / ✕ / spinner icons with text.
  - The diff uses `-`/`+` glyphs and visually hidden "Removed line"/"Added line" labels.
  - Coverage chips include status words.
- **Keyboard:**
  - Logical tab order: top bar → left → findings → detail → right.
  - "Skip to findings" link.
  - Visible focus: a 1px `#00F0FF` outline, 2px offset, plus glow, on every interactive element, never removed.
  - Table supports arrow keys; Esc closes the drawer and stops the mic; ⌘/Ctrl+Enter opens the PR.
  - Every shortcut is shown in the UI and can be remapped or disabled.
- **ARIA:**
  - Gauge: `role="meter"` with `aria-valuemin="0"`, `aria-valuemax="100"`, `aria-valuenow="82"`, `aria-valuetext="82 out of 100, Critical risk"`, plus a visible label.
  - Diff: a `region` with `aria-label="Proposed fix diff for app/kyc/service.py line 42"`. Each pane is a labelled `figure`, and line content is readable as text, not images.
  - Findings table uses a native `<table>`, `<caption>`, `scope="col"` headers and `aria-sort`.
  - Scan progress: `role="progressbar"` plus a polite live region for status changes; critical errors use `role="alert"`.
  - Icon-only buttons (mic, send, attach, avatar) have `aria-label`s.
- **Motion:** respect `prefers-reduced-motion` by disabling the mic pulse, gauge sweep and shimmer.
- **Text scaling:** the layout survives 200% zoom and reflows to one column at 320 CSS px.
- **Privacy-by-design UX:** raw PII is never rendered. Previews pass through Gemma redaction (`/api/redact`) and show masked values such as `XXXX-XXXX-1234`.

## 8. Component → backend API mapping

| Component | Endpoint | Method | Notes |
|---|---|---|---|
| Top bar · Run Scan, scan status pill | `/api/scan` | `POST` starts a scan (`{repo, branch}` → `{scan_id}`); `GET /api/scan/{id}` polls or streams status | Drives Scanning / Error states in every panel |
| Risk score gauge, severity cards, DPDP coverage chips | `/api/scan/{id}` (summary) or `/api/findings?scan_id=` (aggregates) | `GET` | `risk_score`, `counts_by_severity`, `coverage_by_section` |
| Findings table, filters | `/api/findings` | `GET` with `?scan_id=&severity=&pii_type=&q=` | Paginated list of `{id, file, line, pii_type, sink, dpdp_section, severity}` |
| Finding detail: diff viewer, citation card | `/api/findings/{id}` | `GET` | Returns `{snippet, proposed_patch, rule_id, citation{section, text, penalty, url}}` |
| Redacted code preview / transcript sanitization | `/api/redact` | `POST` | Gemma-based redaction of snippets and of any text sent to LLMs |
| Auto-Fix PR panel: checklist + Open Pull Request | `/api/fix-pr` | `POST {finding_id}` → `{verification: {rescan_clean, no_new_findings, compiles}, pr_url}` | Button stays disabled until all checks pass |
| Ask the Auditor (voice / text) | `/api/ask` | `POST {question, finding_id?}` (text); Gemini Live session for voice | Question context is redacted via `/api/redact` before reaching the model |
| Footer telemetry | — | — | Scan events are logged to BigQuery server-side |
